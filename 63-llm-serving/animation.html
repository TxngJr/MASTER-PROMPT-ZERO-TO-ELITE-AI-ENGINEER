3. operational metrics ต้องเก็บเป็น distributions

โจทย์และเหตุผล

p50/p95/p99 บอก tail latency ที่ mean ปิดบัง readiness ไม่เหมือน liveness และ autoscaling มี start-up delay ต้องวาง bounded admission/backpressure ก่อน overload ลุกลาม

ตัวอย่างและคำอธิบาย

Define liveness and readiness separately.

livenessถามprocessยังตอบได้หรือไม่,readinessถามmodelloaded/warm/รับtrafficได้หรือไม่; loadingอาจlive=true,ready=false

สัญลักษณ์ / input controls

elapsed: elapsed startup ms,initial=500; loadTime: model load time ms,initial=300; warmup: warmup duration ms,initial=100; newError: canary errors /100,initial=1; errorLimit: allowed errors /100,initial=3

แทนค่าจริงทีละ operation

  1. shape / range = [500, 300, 100]; กำหนดความหมายและหน่วยของ input ก่อนทดลอง
  2. ready=elapsed≥load+warmup; rollback=error>limit = "canary"; process alive กับ model ready เป็นคนละเงื่อนไข; error gate ปิด traffic ไปเวอร์ชันใหม่
  3. normal / boundary / comparison = "canary"; ตรวจค่าจริงและเทียบกับ baseline โดยคงตัวแปรอื่น

ก่อนเปลี่ยนค่าหนึ่งตัว ให้ทำนายว่า output และค่าระหว่างทางใดควรเปลี่ยน แล้วคงตัวอื่นเพื่อทดสอบเหตุผลของคุณ

"""Serving SLO, capacity, and rollout calculations."""

from __future__ import annotations

import math
import numpy as np


def percentile(
    values: list[float],
    q: float,
) -> float:
    if not values:
        raise ValueError("values must be non-empty")
    if not 0.0 <= q <= 100.0:
        raise ValueError("q must lie in [0,100]")
    if any(value < 0 for value in values):
        raise ValueError("latencies must be non-negative")

    return float(np.percentile(np.asarray(values, dtype=float), q))


def request_latency(
    *,
    queue_seconds: float,
    prefill_seconds: float,
    decode_seconds: float,
    network_seconds: float = 0.0,
) -> float:
    values = [
        queue_seconds,
        prefill_seconds,
        decode_seconds,
        network_seconds,
    ]
    if any(value < 0 for value in values):
        raise ValueError("latencies must be non-negative")
    return float(sum(values))


def throughput(
    *,
    completed_units: int,
    elapsed_seconds: float,
) -> float:
    if completed_units < 0:
        raise ValueError("completed_units must be non-negative")
    if elapsed_seconds <= 0:
        raise ValueError("elapsed_seconds must be positive")
    return float(completed_units / elapsed_seconds)


def success_rate(
    *,
    successes: int,
    total_requests: int,
) -> float:
    if total_requests <= 0:
        raise ValueError("total_requests must be positive")
    if not 0 <= successes <= total_requests:
        raise ValueError("successes out of range")
    return float(successes / total_requests)


def little_law_concurrency(
    *,
    arrival_rate_per_second: float,
    average_latency_seconds: float,
) -> float:
    if arrival_rate_per_second < 0:
        raise ValueError("arrival rate must be non-negative")
    if average_latency_seconds < 0:
        raise ValueError("latency must be non-negative")
    return float(
        arrival_rate_per_second * average_latency_seconds
    )


def required_replicas(
    *,
    offered_requests_per_second: float,
    sustainable_requests_per_second_per_replica: float,
    target_utilization: float = 0.7,
) -> int:
    if offered_requests_per_second < 0:
        raise ValueError("offered load must be non-negative")
    if sustainable_requests_per_second_per_replica <= 0:
        raise ValueError("replica capacity must be positive")
    if not 0.0 < target_utilization <= 1.0:
        raise ValueError("target_utilization must lie in (0,1]")

    usable = (
        sustainable_requests_per_second_per_replica
        * target_utilization
    )
    if offered_requests_per_second == 0:
        return 0
    return int(math.ceil(offered_requests_per_second / usable))


def token_rate_limit_cost(
    *,
    input_tokens: int,
    output_tokens: int,
    output_weight: float = 1.0,
) -> float:
    if input_tokens < 0 or output_tokens < 0:
        raise ValueError("token counts must be non-negative")
    if output_weight < 0:
        raise ValueError("output_weight must be non-negative")
    return float(
        input_tokens + output_weight * output_tokens
    )


def canary_split(
    total_requests: int,
    *,
    canary_fraction: float,
) -> tuple[int, int]:
    if total_requests < 0:
        raise ValueError("total_requests must be non-negative")
    if not 0.0 <= canary_fraction <= 1.0:
        raise ValueError("canary_fraction must lie in [0,1]")

    canary = int(round(total_requests * canary_fraction))
    stable = total_requests - canary
    return stable, canary

รูปทรงข้อมูล: (B,T,d) หมายถึง batch × เวลา/ตำแหน่ง × features; ใช้ชื่อแกนกำกับเสมอ การ transpose เปลี่ยนแกนแต่ไม่ใช่แค่เปลี่ยนชื่อ
batch
กลุ่มตัวอย่างที่คำนวณร่วมกันหนึ่งครั้ง; B คือจำนวนตัวอย่าง ไม่ใช่จำนวน features หรือจำนวน optimizer updates
weight w / θ
น้ำหนักหรือพารามิเตอร์ที่โมเดลใช้คำนวณ; แก้ด้วยมือทำ forward ใหม่ ส่วน optimizer ต้องรับ gradient แล้วกด update จึงแก้ state
bias b
ค่าคงที่ที่บวกกับผลเชิงเส้น; regression scalar bias เพิ่ม Δ ทำให้ prediction ทุกจุดเพิ่ม Δ เท่ากัน
prediction ŷ
ค่าที่โมเดลทำนายจาก input และพารามิเตอร์ปัจจุบัน; เครื่องหมายหมวกแยกจาก target y ที่มาจากข้อมูล
residual e
ความคลาดเคลื่อน ในเว็บนี้นิยาม prediction − target; บางตำราใช้เครื่องหมายกลับกัน จึงต้องตรวจนิยามก่อนเทียบสูตร gradient
MSE
mean squared error = ผลรวม residual กำลังสองหารจำนวนรายการที่ระบุ; มีหน่วยเป็น target ยกกำลังสอง และการใช้ sum แทน mean เปลี่ยน scale gradient
loss L / objective J
จำนวนที่ optimizer ต้องการลด; objective อาจรวม data loss และ regularization จึงต้องดูองค์ประกอบและ reduction ให้ตรง implementation
gradient ∇ / ∂
เวกเตอร์ของ partial derivatives บอกอัตราเปลี่ยน loss ต่อพารามิเตอร์แต่ละตัว; ∂ ใช้เมื่อเปลี่ยนตัวหนึ่งโดยตรึงตัวอื่น
chain rule
กฎลูกโซ่: คูณอนุพันธ์ตามเส้นทาง และบวก contribution จากทุกเส้นทางที่มารวมกัน ใช้ย้อนจาก loss ถึง weights
learning rate η
ขนาดตัวคูณ gradient ใน update θnew=θ−ηg; η≥0, ศูนย์หมายถึงไม่มีการขยับพารามิเตอร์ ก้าวใหญ่เกินอาจ diverge
regularization λ
ตัวคูณค่าลงโทษ ต้อง λ≥0 ตามนิยามการลงโทษ; Ridge λΣw² เพิ่ม gradient 2λw โดยบท Regression นี้ไม่ลงโทษ bias
baseline
สถานะอ้างอิงที่ตรึงไว้สำหรับเทียบ; ต้องเก็บ snapshot ไม่อ้าง object ปัจจุบันที่แก้ตามไปด้วย
invariant
คุณสมบัติที่กลไกต้องรักษา เช่น probability รวม1, shape สอดคล้อง, queue ไม่เกิน capacity; ใช้ tests ตรวจได้มากกว่าดูภาพสวย
optimizer state
ความจำของอัลกอริทึม เช่น velocity, moments และ completed updates; คืนเฉพาะ weights ยังไม่เท่ากับเริ่มการฝึกใหม่ทั้งหมด
finite difference
ประมาณ derivative ด้วย [f(x+h)−f(x−h)]/(2h); h>0, ใช้ smooth point และลองหลาย h เพื่อแยก truncation error จาก roundoff
softmax
แปลง logits เป็นความน่าจะเป็นตามแกนที่กำหนด; ลบ max ก่อน exp เพื่อความเสถียร และ fully masked row ต้องมีนโยบายชัดเจน
logit
คะแนนก่อน sigmoid/softmax ไม่ใช่ probability; อาจเป็นจำนวนจริงติดลบหรือเกิน1ได้ จึงห้ามส่งให้ loss ที่คาด probability โดยไม่แปลง
temperature τ / T
ตัวหาร logits ก่อน softmax; ต้องเป็นบวก ค่าเล็กทำ distribution แหลมขึ้น โดยไม่เท่ากับ retrain weights
mask
ตัวกำหนดตำแหน่งที่อ่านหรือคิด loss ได้; causal mask ปิดอนาคต, padding mask ปิดข้อมูลเติม, loss mask เลือก target แต่ละอย่างคนละหน้าที่
Q / K / V
query ใช้ค้นข้อมูล, key ใช้จับคู่ query, value เป็นข้อมูลที่ถูกถัวเฉลี่ย; เป็น learned projections ของ representation ไม่ใช่ป้ายความหมายตายตัว
head
ส่วนของ feature representation ที่ทำ attention แยกกัน แล้ว concat/project กลับ; ต้องตรวจ d_model หารจำนวน heads ลงตัว
ε-neighborhood
เพื่อนบ้านทั้งหมดที่มีระยะไม่เกิน ε รวมจุดตัวเองใน DBSCAN นี้; ε มีหน่วยเดียวกับพิกัด ไม่ใช่จำนวน k ที่ใช้โหวต
core / border / noise
DBSCAN core มีเพื่อนบ้านรวมตัวเองถึง min_samples; border อยู่ใกล้ core แต่เพื่อนบ้านไม่ถึง; noise ไม่ถูกเชื่อมกับ core cluster ใด
bootstrap
สุ่ม observations แบบ replacement ขนาดเท่าเดิมซ้ำหลายครั้งแล้วคำนวณ statistic ใหม่; seed ทำให้ตรวจซ้ำได้ แต่ไม่แก้สมมติฐาน IID ที่ผิด
confidence interval
ช่วงที่สร้างด้วย procedure ที่มี coverage ตามสมมติฐาน; ช่วงหนึ่งที่ได้แล้วไม่ใช่ posterior probability ของ parameter และ sample เล็กยังไม่แน่นอนมาก
validation / test
validation ใช้เลือกโมเดล/ค่าตั้ง ส่วน test ใช้ประเมินหลัง freeze การตัดสินใจ; fit preprocessing/tokenizer จาก test เป็น leakage
leakage
ข้อมูลที่ควรยังไม่รู้ไหลเข้า training/การเลือกโมเดล เช่น future feature หรือเอกสารซ้ำข้าม split ทำให้ metric ดูดีเกินการใช้งานจริง
queue / capacity
queue คือรายการรอ, capacity การให้บริการรวม = workers × service rate ตามแบบจำลอง; เพิ่ม timeout ไม่เพิ่มกำลังประมวลผล
state transition
การเปลี่ยนสถานะเมื่อเกิดเหตุการณ์ที่อนุญาต เช่น queued→active→done; ต้องระบุ guard, side effect และเหตุผลเมื่อ transition ถูกปฏิเสธ
latency / throughput
latency คือเวลาต่อคำขอ, throughput คือปริมาณงานต่อหน่วยเวลา; batching อาจเพิ่ม throughput แต่เพิ่มเวลารอ จึงต้องวัดทั้งคู่
idempotency
ทำคำขอ business operation เดิมซ้ำแล้ว side effect เกิดครั้งเดียวตาม key และ transaction protocol; ไม่ได้รับประกันจากการใช้ UUID ใหม่ทุก attempt
local lab
โปรแกรม Python และ tests ที่ผู้เรียนรันบนเครื่อง; เว็บเก็บเพียงคำยืนยันของผู้เรียน การผ่าน tests ของโค้ดต้นแบบไม่ใช่ผลตรวจโค้ดผู้เรียน

Batch 21 Integration Project — Quantized Inference & Serving Capacity Lab

Batch 21 connects low-bit model storage, KV-cache capacity and production serving metrics.

Part A — Quantization

A synthetic weight matrix is quantized with:

FP weights
├── INT8 symmetric
├── INT4 symmetric
└── INT4 per-channel

Report: - reconstruction MSE - ideal raw weight bytes - compression ratio vs FP16 - per-channel scale count

Part B — Inference Capacity

Estimate a 32-layer decoder cache under:

MHA: 32 KV heads
vs
GQA: 8 KV heads

Also report: - padding efficiency - paged block fragmentation - prefix-cache saved tokens - speculative acceptance rate

Part C — Serving SLO Planner

Synthetic request traces produce: - p50 / p95 / p99 latency - Little's-Law concurrency - required replica estimate - success rate - 5% canary traffic split

Part D — PyTorch Weight-Only Smoke

Quantize/dequantize one linear weight tensor and compare its output with the FP32 source tensor.

This is an educational reconstruction test, not a claim that NumPy quantization matches an optimized production low-bit kernel.

Run

python integration-project-batch21/src/quantized_inference_serving_lab.py --mode quantization
python integration-project-batch21/src/quantized_inference_serving_lab.py --mode capacity
python integration-project-batch21/src/quantized_inference_serving_lab.py --mode serving
python integration-project-batch21/src/quantized_inference_serving_lab.py --mode torch-weight-only --bits 4
